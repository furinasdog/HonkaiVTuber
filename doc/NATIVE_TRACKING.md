# 动捕后端与宿主映射

## 默认后端

应用默认通过 [MotionCapture](https://github.com/furinasdog/MotionCapture) 插件在本进程内使用 MediaPipe。仓库名称与 UE 内部模块名称不同：本地路径和模块仍为 `Plugins/HonkaiMotionCapture` / `HonkaiMotionCapture`。

插件负责摄像头、原始面部/上半身/双手识别和完整快照；`FNativeTracking` 负责适配及状态；`UVtuberRigComponent` 负责通用骨骼和形变映射。它们不解析或修改角色文件。安装运行库、C++ 状态机和数据字段以[插件文档](../Plugins/HonkaiMotionCapture/README.md)为准。

“开启动捕”会先结束离线回放，再请求启动真人摄像头。开始请求成功不等于识别已成功，界面还会显示初始化、追踪、失追或错误。软件默认不打开摄像头。双手可见数为 0 不代表捕捉线程未运行。

## 用户配置

[使用指南](USAGE.md)介绍识别结果预览、关键点、手动映射、默认手臂角度及完整配置向导。向导记录舒适动作，而非极限幅度；中位动作满值向放松阈值内收约 10%，保留抗噪死区和最小有效范围。既有配置不会自动覆盖，须重新记录并应用建议。

躯干和肩臂使用小角度滞回、至少约 0.08 秒平滑和短暂丢点保持；头部、表情、手指的响应独立。眼形与口型以通用语义混合预算防止重复叠加过驱，不能自动推断所有自定义形变的几何含义。修改后需要真人验收，不以静态截图或数值测试代替。

## 可选独立后端

`Tools/NativeTracking` 是开发和故障诊断用的原生 EXE/AppContainer 回退实现，保留固定协议与构建源码；默认发行流程使用进程内插件。只有进程内 `Start` 同步返回不可启动，并且完整回退运行库已存在时，宿主才尝试它；已经排队后才出现的异步 SDK/摄像头错误不会静默切换后端。

需要诊断该实现时，从仓库根目录运行：

```powershell
./Scripts/Prepare-NativeTracking.ps1
./Tools/NativeTracking/bin/HonkaiNativeTracking.exe --list-cameras
```

准备脚本获取固定版本的 MediaPipe DLL 与通用识别权重并校验哈希，C API 头文件随源码固定；随后使用本机 UE OpenCV 与工具链构建。它不同于不下载依赖的最终发行构建脚本。不要为排错关闭安全软件或更改系统摄像头权限；先检查系统许可、设备占用与实际错误。

宿主为独立后端生成独立 job 目录和父进程 ID。broker 采集图像，worker 进行推理，以原子 `frame.json` 发布 schema 1 完整帧；停止通过同目录 stop 文件和父进程生命周期管理。框架不以旧/默认关键点替代有效追踪。该回退后端不提供识别面板的摄像头图像预览。

## 测试与隐私

运行库状态、映射、原子保存与合成输入回归见[开发说明](DEVELOPMENT.md)。真人测试应分别报告采集帧率、推理帧率、追踪有效性、映射结果、停止/重启和画面延迟。

摄像头预览与原始快照是敏感数据。提交问题时使用去除个人信息、已授权的最小复现；不要提交本机录像、识别权重、运行库或角色素材。协议与字段细节见[插件集成说明](../Plugins/HonkaiMotionCapture/doc/INTEGRATION.md)。
