# 使用说明

本文适用于 HonkaiRendering 与 HonkaiVTuber。两个应用目前共享操作与功能；主项目侧重角色展示，VTuber 侧重动捕工作流。以下描述当前源码行为，旧发行包可能尚未包含全部功能，请先查看“应用 → 关于”的版本。

## 安装与首次启动

使用完整 Windows x64 发行目录，运行 `HonkaiRendering.exe`。不要只复制 EXE；旁边的 `Engine`、`HonkaiRendering`、`Licenses` 等目录是运行依赖。默认窗口模式，显示中性灰背景，不自动开启摄像头。

首次运行依次展示项目开源许可、第三方许可、模型与生成内容说明。阅读并勾选确认后继续，不同意会退出。许可文本变化时可能再次要求确认。随后显示一次拖入 ZIP 的引导；完成后菜单默认隐藏。

初始化时显示项目加载提示。启动图是否包含 Epic Logo 取决于该发行版本使用的授权素材，不能以 Logo 是否出现判断加载成功。

## 导入角色

1. 将一个包含 PMX 和贴图的 ZIP 拖入窗口，或在“模型 → 导入 ZIP 压缩包”中选择文件。
2. 选择压缩包中的 PMX。保留 PMX、贴图和说明文件的相对目录，不要只打包 PMX。
3. 阅读原包中的使用守则。面板须在前台可见至少 5 秒，再勾选确认才能继续；取消保留已加载角色。

当前入口支持普通 ZIP，不支持直接拖入 RAR、7z 或单独 PMX。压缩包最大 512 MiB，单个解压文件最大 256 MiB、合计最大 1 GiB、最多 20,000 个条目；不接受越界路径、重复目标与符号链接。超出限制的模型包需要先合法整理，不能通过重命名扩展名绕过检查。

常见文本守则直接显示；图片、PDF、过长或未识别的说明请通过“打开说明目录”检查原文件。没有找到说明不表示模型没有使用限制。软件许可与模型许可相互独立。

程序使用导入副本，不修改原始压缩包。缺图、特殊球面模式、非常规骨骼和复杂表情可能需要模型作者或使用者调整；不是所有 PMX 都能得到相同的渲染和动作质量。

## 视角与菜单

| 操作 | 功能 |
| --- | --- |
| 中键拖动 | 绕角色旋转视角 |
| Shift + 中键 | 平移视角 |
| Ctrl + 中键、滚轮 | 缩放 |
| WASD | 水平移动角色，按下及松开时平滑加减速 |
| E / Q | 上移 / 下移角色 |
| 小键盘 1 / 3 / 7 | 正面 / 右侧 / 顶部视图；配合 Ctrl 查看反向 |
| 小键盘 5 | 正交 / 透视 |
| 小键盘小数点、Home | 重新聚焦角色 |
| H | 隐藏或恢复导航及浮动页面 |
| Esc | 隐藏时恢复界面；有子页时先关闭子页，否则切换界面显隐 |

菜单分为模型、捕捉、映射、画面、场景、应用，在同一视口内浮动，可拖动或收起。普通浮窗外仍可操作视角；输入框取得焦点时键盘用于编辑。首次协议、模型守则、模型选择及加载状态会限制底层操作。

右上角“渲染 FPS”统计游戏循环帧间隔，“识别 FPS”统计识别处理速度；二者不一定相同，也不是摄像头到显示的端到端延迟。停止摄像头或数据过期后，识别值显示 0。

## 开启动捕

1. 导入角色，点击导航中的“开启动捕”，或进入“捕捉”点击同名按钮。
2. 查看状态文字。启动是异步的，初始化、未识别人脸、依赖缺失和摄像头错误都会显示状态；点击成功不代表已经识别到人。
3. 在“识别结果”查看摄像头画面、叠加关键点、面部/上身/双手状态、头部角度和表情数值。
4. 正对镜头保持自然姿态，再使用“校准当前姿态”。

当前默认使用 UE 进程内后台线程和动态 MediaPipe DLL。未准备运行库时会明确报错；若安装了旧独立后端，宿主可尝试该回退，状态会标明。它不是已实现的静态链接识别器。预编译 SDK 有自身遥测行为与停止时延限制，详见 [MotionCapture](https://github.com/furinasdog/MotionCapture) 的说明。

设备编号、分辨率、帧率上限、置信度和镜像在“捕捉”页设置。先停止摄像头，再调整配置并重新启动。界面显示“正在停止”时等待驱动释放，不要反复点击。画面过暗、手离开镜头、遮挡或可见度低都可能使部分动作失效。

隐藏或关闭识别结果页面不会停止动捕；“停止”才会停止追踪并请求释放设备。识别预览复用同一摄像头，不会另开一个采集源，也不进入 Spout 输出。

开发回放模式会明确提示“不占用摄像头”。点击“开启动捕”会先结束离线回放，再尝试启动真人摄像头，不需要另找“切换至真人”操作。

## 映射与标定

“映射”包含面部、手臂与手、选项三个标签。选择输入通道及模型已有的形变或骨骼，再调整启用状态、反向、平滑、灵敏度、响应范围等。模型没有相应表情或骨骼时，仅调阈值不会创造新动作。

“映射配置向导”会逐步采样放松嘴部、张嘴、微笑、自然睁眼、闭眼，以及嘟嘴、O 形嘴、咧嘴、嘴左右移动、眯眼、睁大、抬眉、压眉和合紧双唇。按提示保持舒适且稳定的动作，不必用力做极限表情；可重录或跳过可选项。采样必须来自新鲜、有效的追踪帧。

最后检查每个通道的原值、建议范围和目标表情，可取消不需要的更改，再点“应用并保存”。向导只在应用时写入配置，未映射的通道可以先保存输入范围。新建议的满值范围略向内收，降低动作误差对触发的影响；旧配置不会被自动重写，需要重跑向导。

“映射 → 选项”中的默认手臂展开角适用于未被有效追踪的手臂：0° 下垂、90° 平举，默认为 20°。有效追踪接管后按输入动作；失追后按回退时间平滑返回。此设置不修改 PMX。

映射页面自动保存并显示结果。出现“保存失败”时检查路径权限、只读文件或同步软件占用，解决后重新保存；不要直接删除唯一配置。

## 渲染与部件

“场景 → 背景颜色”切换中性灰、浅灰、深灰。“画面 → 相机与抗锯齿”选择 TSR、DLAA 或 DLSS 质量模式，以及标准/高质量内部分辨率。

选择标准 100% 或高质量 150% 内部分辨率会关闭 DLSS，并恢复宿主的抗锯齿路径。

默认 TSR。NVIDIA 选项只有在发行版本包含官方插件、硬件与运行时受支持时可用；不可用时显示原因。DLSS 仅作用于主视口，UI 按窗口分辨率绘制，独立 Spout 捕获不自动继承 DLSS。当前不提供帧生成与光线重建开关。高内部分辨率增加 GPU 负载，不能保证性能更高或所有细线都无闪烁。

“模型 → 生成增强效果”使用 Blender/MMD Tools 生成可编辑的面部控制数据。工具准备会先查找兼容的本地安装；缺少时可能下载经固定哈希校验的便携工具。任务在后台运行，可取消；完成并验证成功后才更新显示。“原效果/增强效果”切换保持相机与灯光不变。“原效果”指增强前的本工具渲染，不是原游戏效果。

画面页的增强贴图 512 / 1024 设置仅影响下一次生成，不会重写已应用的结果。

无法自动确定面部时，使用“选择面部材质”的高亮预览明确选择。自动生成的数据不等于原游戏的 FaceMap、LightMap 或美术还原，复杂 UV 和拓扑可能仍需人工处理。导出增强数据不会赋予再次分发源素材的权利。

“模型 → 部件显隐”可预览和隐藏独立部件，按模型保存在本机。关闭“启用部件隐藏”或“恢复所有部件”可恢复原始显示。它不编辑 PMX，也不能保证所有模型的眼睑线等都恰好是独立部件。

头发、衣物与配饰使用模型原有 PMX 刚体/关节数据。没有这些数据不会自动生成物理。极端动作、刚体约束冲突或碰撞数据不合理时仍可能穿插、漂移或抖动；应以实际动态画面检查。

## OBS / Spout 输出

进入“画面 → OBS 视频输出”开关发送，在支持 Spout 的接收端选择 `HonkaiVTuber`。当前输出为 1280 × 720、30 FPS，跟随相机，通过独立角色捕获排除菜单和识别预览。

需要接收端安装合适的 Spout 支持。当前输出为不透明画面，Alpha 固定为 1；接收端色彩、窗口最小化及设备兼容性须在自己的环境检查，不要把预览正常当作接收端已经正常。

## 配置与问题排查

“应用”或“画面 → 相机与抗锯齿”可以打开用户数据目录。导入副本、增强任务、工具与缓存在应用各自的用户数据目录；模型映射位于运行实例的 UE `Saved/Mappings`，日志通常位于 `Saved/Logs`。可从日志或实际运行目录确认位置，不要假设可执行文件所在目录就是全部用户配置。

“清理生成缓存”只清除生成缓存，保留导入副本、源资源与工具；之后可以重新生成。清理前先备份希望保留的增强结果。

| 问题 | 首先检查 |
| --- | --- |
| ZIP 被拒绝、缺贴图 | 格式和大小限制、相对目录、完整错误提示 |
| 点击动捕后无动作 | 是否已导入、状态文字、摄像头权限/占用、运行库是否完整、是否识别到人 |
| 闭眼、嘴部过驱或不触发 | 正确目标形变、重复映射、标定范围与实际输入；重新运行向导 |
| 身体方向或幅度不合适 | 镜像、中立姿态、映射开关、灵敏度和模型骨骼 |
| 衣物或配饰抖动/穿插 | 默认手臂角度、模型原有物理，停止动捕后是否仍复现 |
| UI 模糊或裁剪 | 窗口大小、Windows 缩放比例、应用构建版本 |
| 输出空白或颜色不同 | Spout 状态、发送名称、接收端插件及色彩设置 |

仍无法解决时，在“应用 → 关于”记录版本、构建时间与插件版本，按[贡献指南](../CONTRIBUTING.md)报告最短复现步骤和脱敏日志。未经允许不要上传模型、个人摄像头画面或追踪录像。
